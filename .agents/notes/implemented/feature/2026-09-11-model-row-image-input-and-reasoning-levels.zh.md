# Agent Note: 模型行的图片输入与推理等级

Status: implemented

[English](2026-09-11-model-row-image-input-and-reasoning-levels.md) | 中文

## 问题

自定义提供方下手动录入的模型，在未声明图片输入之前一律按纯文本对待，未声明推理等级时其模型选择器也不会提供 Effort 菜单。这两个声明只存在于 pi-ai 配置的 `models[]` 条目里，而模型页——大多数用户会打开的界面——对两者都没有控件：一行模型只暴露 ID、显示名称、上下文窗口和最大输出 token 数，到此为止。这两个缺口出现在不同的高度上。给手动录入的模型附加图片，会在发送前被拒绝并点名该模型，而修复办法只以 `settings.yaml` 配方形式记录着。对于端点自身确实会思考的路由，则只能拿到端点自己的默认值，因此找不到推理等级控件的用户无法判断模型是否真的会思考。

## 决策

模型行的**高级**折叠区现在提供这两个声明，并写入 `settings.yaml` 使用的同一批 `models[]` 条目，使页面与配置文件保持等价互换，而不是让页面成为配置文件的有损子集。

**图片输入**——**继承**/**仅文本**/**文本和图片**：继承会省略 `input`，使已安装目录的记录生效，并为目录未描述的模型回退到该路由的 `defaultInput`；仅文本写入 `input: [text]`；文本和图片写入 `input: [text, image]`。

**推理等级**——**继承**/**关闭**/**自定义等级**：继承会移除该键，使已安装目录的等级保持生效；关闭写入 `reasoningEfforts: false`；自定义等级会打开一个基于 `REASONING_LEVELS`（`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`）的等级编辑器。每个等级是一个复选框加一个发送值输入框，且发送值仅在等级被勾选时可编辑。切换到自定义等级时会播种 `{ off: null, high: 'high', max: 'max' }`，即[按模型的推理声明](../../archived/feature/2026-08-08-pi-ai-per-model-reasoning-declarations.md)决策所记录的配置形状，使首次写入即可用，而不是一个会被适配器拒绝的空映射。已勾选等级上留空的发送值会存为 `null`，这是 `off` 所使用的“不发送该字段”形式。

`validateDeepSeekModels` 现在会在写入前拒绝这两种形状，与适配器的配置 schema 一致：图片输入只能列出 `text` 和 `image`；`reasoningEfforts` 映射只能使用已知等级，必须为除 `off` 外的每个等级填写发送值，且至少提供一个 `off` 之外的思考等级。`false` 与省略该键都被接受。

## 考虑过的替代方案

**两个字段都保持仅在 `settings.yaml` 中，并从行上链接到该配方。** 该配方对编辑配置的人已经够用，但图片拒绝发生在发送时——用户在得知模型需要声明之前就已经附加了图片——而推理等级的缺失完全无法诊断：缺少 Effort 项并不能说明模型是否能思考，还是仅仅未被声明。

**把它们做成路由级控件而不是逐行控件。** 路由级的 `defaultInput` 和 `reasoning` 已经作为回退值存在，路由级控件也只需要两个字段而不是每行两个。但同一条路由下的模型并不一致：网关会同时提供纯文本模型和视觉模型，同一路由的模型对可接受的等级也各执一词。路由级控件若要把两种情况都表达出来，就只能收窄或开启该路由上的全部模型。

**把等级渲染成单个逗号分隔的文本字段。** 发送值确实是不长的字符串，但单个字段无法表达“off 不发送任何字段，而其他每个等级都需要取值”——整个功能正建立在这个区别之上——且等级名称中的拼写错误只会在适配器拒绝请求时才暴露出来。

## 后果

手动录入的模型可以在配置它的那个页面上完成全部声明：图片拒绝与空白的 Effort 菜单都会在配置时变得可见，同一条目仍然可以在 `settings.yaml` 中手工编辑，因为页面写入的是适配器自身的形状，而不是页面私有的形状。高级折叠区现在携带四个字段，等级编辑器也是页面上最大的控件；其上方提示承担了选择器菜单无法表达的 off/留空规则。`settings.yaml` 仍然是表单未收录字段的归属处——兼容性开关、请求头、超时、重试策略，以及路由级的 `defaultInput` 和 `reasoning` 回退值。
